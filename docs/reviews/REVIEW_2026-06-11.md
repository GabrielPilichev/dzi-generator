### 🟡 YELLOW — keep in mind, not urgent

**Y1. f-string SQL: 16 sites (`web/app.py:746, 1125, 1159, 2007, 2084, 2343,
2411, 2434, 2636, 2655, 2725, 3014, 3173, 3627, 3812`)**
All audited — every one is either:
  - a `?`-placeholder list built from a static `","`.join (safe)
  - a column/table name resolved through `ALLOWED_INTERNAL_TABLES` whitelist
    or `first_existing_column(sqlite_table_columns(...), KNOWN_TUPLE)` (safe,
    since the candidate tuple is a Python literal — attacker can't reach in)
  - a hardcoded ORDER BY built from a whitelisted column (safe)

No injection risk found. **But** the pattern is fragile under maintenance —
one careless edit lands a CVE. Worth a `# SAFE: column from whitelist` comment
on each f-string `execute(` at minimum, and ideally a small helper
(`safe_column_query(conn, sql_template, column_key, params)`) that enforces
the whitelist at the call site.

**Y2. CSRF: not enabled**
No `Flask-WTF` / `CSRFProtect`. POST routes (`/teacher/new`,
`/teacher/assignment/<id>/edit`, `/teacher/assignment/<id>/duplicate`,
practical upload, quiz submit) rely solely on session cookie + same-site Strict.
Same-site Strict is a strong mitigation in modern browsers, but a CSRF token
on state-changing forms is the standard belt+suspenders. Low priority for a
local-school deploy, real for any public exposure beyond cloudflared smoke.

**Y3. Tester role is shared, not per-teacher (README admits this)**
Multi-tenancy is not implemented. The `teacher_results`, `teacher_assignments`
endpoints leak across teachers in a multi-school deploy. README flags this as
"intentional for local/single-school". Confirm with dawg whether his deploy
target shifted — if yes, this is RED, not YELLOW.

**Y4. `vault/` and `data/questions.db` are tracked in git**
The 2.5MB SQLite DB is committed. README says "data/questions.db path is ignored"
but the file is already in. Either by design (seed DB shipped with repo) or
oversight. If by design, document it; if not, `git rm --cached` and rely on
migrations + a seed script.

**Y5. PRAGMA table_info(`{table}`) on line 1125**
`{table_name}` is checked against `ALLOWED_INTERNAL_TABLES` at line 1121 — safe.
Worth a comment.
